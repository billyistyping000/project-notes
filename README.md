# 專案記事

個人用的專案工作台與記事，方便記錄每單做到邊、關鍵日期和機種情況，並以「填好 → 驗證 → 被問 → 記入缺口 → 補料再驗證」的方式，讓回覆愈來愈即答。全部程式都在 `index.html`，不需要安裝、不需要帳號、也不需要開伺服器。資料存在這台裝置的瀏覽器裡。

沒有後端，沒有追蹤。除非你在「設定」裡自己按下測試、拉取或推送，或在「即時解答」裡按下「問外部 API」，否則不會把資料送到任何地方。合約和其他文件不會上傳到公開網站。

## 說明頁

在側欄或手機右上角打開「說明」，可以看到：

- 這個工具的寫法（單一 HTML、本地儲存、按鈕如何分配功能）
- 持續改良與驗證的工作方式，以及就緒狀態（尚欠資料、待驗證、可即答）
- 每一個按鈕和功能的用途，包括專案欄位、文件連結、即時解答、記入要補和驗證
- 目前用 ChatGPT、Copilot 等 AI 做這類個人工具時，比較穩陣的做法
- 如何自行接上外部 API 來問合約內容，而又不用把檔案放到公開網站

每個按鈕都有對應功能。如果出現尚未接上的按鈕，畫面會提示，而不會沒有反應。

## 工作台：先睇日期和現況

打開工具就會進入「工作台」。第一眼用來應付突擊提問：每張專案卡顯示就緒狀態（尚欠資料、待驗證、可即答）、目前情況，以及機種重點（新裝／現代化、全改／部分改、有機房／無機房、保留項目、開工狀態）。

日期用大字或色塊標出：

- **剩餘 N 天**：該期限還沒到
- **今天到期**
- **逾期 N 天**：日期已過，而且專案不是「已完成」或「已取消」
- **未設結束日**／**未設開始日**／**未設日期**：還沒填
- **已完成**、**已取消**：即使日期已過，也不會標成逾期
- **等候開工**／**已開工**：依據開工日和開工狀態。未填狀態時，會按開工日推斷

工作台會把以下項目分開列出：

- **本輪要補／要驗證**：尚欠資料而且日期有風險、資料已改、尚未驗證，或驗證已超過十四日的進行中專案
- **要補項目**：尚未補完的缺口紀錄
- **已逾期**：結束日、已過而仍在等候的開工日，或其他未完成期限（例如完工、驗收）
- **本週到期**：未來七天內（含今天）的上述期限
- **等候開工**：尚未標成已開工的進行中專案
- 其他未完成、已完成

已完成或已取消的專案不會出現在「本輪要補／要驗證」，也不會算進逾期。工作台上的「尚欠資料」「待驗證」「可即答」數字只計算未完結專案，點進去可篩選列表。

專案頁可以搜尋（包括情況、機房、保留項目、就緒狀態）、依狀態和期限篩選（含「等候開工」「尚欠資料」「待驗證」「可即答」），並依開始日、結束日、狀態或名稱排序。版面可切換「卡片」或「時間軸」。

第一次打開會載入示範資料，用來展示日期、欄位，以及三種就緒狀態和一項要補例子。示範內容是虛構的升降機／自動梯例子，不是真實合約或真實 TKE／房委會項目。可以修改，或在橫額／設定裡清除。一經修改的項目就不再算示範，清除時會留下來。

## 專案欄位

每個專案除了名稱、狀態、開始日、結束日、說明和標籤，還有：

- **目前情況／做到邊**：短句，會顯示在工作台卡片上
- **項目類型**：新裝／現代化／其他，可不填
- **現代化範圍**：全改／部分改；只在類型是現代化時顯示
- **機房**：有機房／無機房
- **保留項目**：自由填寫這一單保留了什麼
- **開工（Work commenced）**：開工日、等候開工或已開工、短備註
- **其他期限**：可新增完工、驗收或自訂名稱的日期。完成的期限不會標成逾期

## 即時解答

工作台有「即時解答」，專案頁有「問呢單」。

1. 可指定專案，或讓工具按問題搜尋。問題可留空，直接整理現況。
2. 按「即時解答」後，會用本機欄位、連結記事，以及可在裝置上讀到的附件文字，整理一段可複製的短回覆（日期、機房、保留項目、全改或部份改、開工狀態，以及讀得到的合約重點）。
3. 按「複製答案」可把回覆放到剪貼簿。
4. 若回覆尚欠欄位或文件，按「記入要補」，把要補項目記在本機。被突擊提問後，也可按「今次被問」，記下問題、能否即答，以及還欠什麼。
5. 若要再問外部 AI，先到「設定 → API 端點」填寫**你自己**的網址和金鑰，再按「問外部 API」。只有按下時才會送出；金鑰只留在這台裝置，放進你指定的標頭。請求本體是問題、專案欄位、記事和已抽出的文字，不含檔案二元內容。沒有端點時，畫面會說明做法。

純文字或可選取文字的 PDF，可以嘗試在裝置上抽出內容。掃描件、圖片或 Word 通常讀不到，工具會說明原因，但仍會保留檔案或路徑連結。不要把合約放到公開網站。

## 改良與驗證（持續進步）

這是之後日常使用這個工具的工作方式，目的是讓每一單愈來愈禁得起突擊提問：

1. **先填你知道的。** 項目類型、機房、全改或部分改、保留項目、目前情況、開工狀態，以及開工／完工／驗收等關鍵日期，隨時可補。需要答合約問題時，在專案頁掛上或記下合約、圖則的位置。
2. **被問之前先驗證。** 欄位齊了之後，到專案頁的「驗證與就緒」，可分別驗證「日期」「機種情況」「合約重點」，或一次驗證全部，並可加一句短備註。工具會記下驗證時間。
3. **答不了就記入要補。** 「即時解答」後若回覆不夠即答，按「記入要補」。實際被問時，用「今次被問」記下那一問。這些紀錄只留在這台瀏覽器，或你自己匯出／同步的備份裡，不會自動送到公開網站。
4. **補完再驗證。** 把要補項目標成「已補完，待再驗證」，或改了已驗證過的欄位／附件後，該單會回到「待驗證」。再確認一次，狀態才會變成「可即答」。

就緒狀態：

- **尚欠資料**：即答所需的欄位或合約／圖則還未齊
- **待驗證**：已經填好，但尚未驗證，或驗證之後資料有改過
- **可即答**：已齊並且目前仍然有效的驗證

建議每天或每週打開工作台，先處理「本輪要補／要驗證」，再睇逾期和本週期限。已驗證超過十四日的項目也會出現在這份清單，方便再確認，但不會單單因為日子久了就失去「可即答」狀態；只有資料改了，或你把要補項目標成已補完，才會回到「待驗證」。

## 合約與文件

在專案頁可以：

- **選擇檔案並存入**：把合約、圖則或往來文件存進這台瀏覽器，並標示類型。匯出備份時可一併帶走。
- **只記下檔名或路徑**：檔案仍留在公司 OneDrive 或共用資料夾，這裡只記住名稱和位置。
- **連結本機或 OneDrive 檔案**（Chrome／Edge 等支援的瀏覽器）：在這台電腦直接連結原檔。這種連結不能寫進 JSON 備份，請另外保留原檔。

記事仍可附加一般檔案。刪除專案時，會刪除該專案的附件，並解除記事的連結；記事本身會保留。

## 電腦（包括不能裝軟件的工作電腦）

1. 把這個資料夾複製到電腦。至少要留下 `index.html`。圖示和 `manifest.webmanifest` 可以不要，頁面仍然可用。
2. 用 Chrome、Edge、Firefox 或 Safari 打開 `index.html`。雙擊，或把檔案拖進瀏覽器視窗。
3. 不需要安裝，不需要網絡，也不需要開命令列。

若頁面是空白的，多半是公司政策封鎖了本地 JavaScript，不是檔案壞了。

## 公司電腦同手機同步（OneDrive）

用法參考 Notion：可以離線修改，連結 OneDrive 檔案後，公司電腦會自動把最新紀錄寫回去。重新打開或回到這個分頁時，如果雲端檔比較新，會自動載入。畫面左上（或手機頂部）會顯示同步狀態。

1. 在 OneDrive 開一個資料夾，例如「專案記事」，把 `index.html`（或 `專案記事.html`）放進去。
2. **公司電腦**：用 Chrome 或 Edge 打開這個 HTML。到「設定」按「儲存到 OneDrive 檔案」，選這個資料夾，檔名建議用 `project-notes-backup.json`。之後改專案或記事會自動更新這個檔。如果本機同雲端都有較新改動，會問你要用邊一面。
3. 等 OneDrive 同步完成。
4. **手機**：用 OneDrive 或「檔案」打開同一個 HTML，到「設定」按「從檔案載入」，揀那份 JSON。iPhone／iPad 通常不能自動寫入資料夾，改資料後請用「匯出備份」下載，再存回 OneDrive。
5. **離線**：HTML 已在裝置上就可以睇和改，不用網絡。公司電腦仍可寫入本機的 OneDrive 資料夾；有網之後 OneDrive 會再同步。兩邊要看到最新進度，先等檔案同步完。

單開一個網站連結可以打開工具外殼，但不會自己登入你的 OneDrive，也不會帶住最新資料。工作紀錄和合約請不要公開放到網上。

## iPhone / iPad

**不要在「檔案」或 OneDrive 的預覽畫面使用。** 預覽只會顯示外觀，不會執行程式，所有按鈕都會沒有反應。

1. 用 AirDrop、郵件或「檔案」App 把 `project-notes.html`（或 `index.html`／`專案記事.html`）存到裝置。
2. 在「檔案」裡找到檔案，點分享（方框加向上箭頭），選擇「用 Safari 開啟」。不要只是點一下用預覽打開。
3. 需要時在 Safari 再選分享 → 加入主畫面。
4. 部分 iOS 版本即使用 Safari 打開，重新整理後資料也可能消失。每次用完請按「設定 → 匯出備份」，把 JSON 和 HTML 放在一起。

### 加入主畫面

加入主畫面需要用 **https** 打開這個頁面（自己的靜態網站即可，這個專案沒有伺服器）。在 Safari 選分享 → 加入主畫面。

直接雙擊的 `file://` 不能加入主畫面，也不能可靠地長期保存資料。`manifest.webmanifest` 和圖示只在 https 時有用。這份工具沒有使用 service worker，避免舊檔被快取；更新時用新的 `index.html` 蓋過即可。

## 備份（重要）

瀏覽器可以清掉本地資料，iPhone、iPad 和無痕模式特別常見。

1. 打開「設定」。
2. 能直接寫入資料夾時（公司電腦的 Chrome／Edge），按「儲存到 OneDrive 檔案」。否則按「匯出備份（下載）」，再把 JSON 放到 OneDrive。檔名建議用英文，例如 `project-notes-backup.json`。
3. 不要只把備份留在瀏覽器裡。
4. 換裝置或資料不見時，按「從檔案載入」或「匯入備份」。可以合併（相同 id 以後來的為準）或取代。

匯出預設包含附件和 API 金鑰。含金鑰的檔案等於密碼，不要傳到不信任的地方。可以取消勾選「包含 API 金鑰」。

附件存在瀏覽器資料庫，匯出時會變成 Base64，所以備份可能很大。單個附件上限 40MB。只記下路徑或本機連結的文件，備份裡通常只有名稱、類型和位置，沒有檔案本身。

舊版備份（第 2 版或更早、沒有就緒或要補欄位的 JSON）仍然可以載入。缺少的欄位會留空或補上預設值，不會丟掉原有專案和記事。要補紀錄（`gaps`）以及專案的 `verification`、`docsMeta` 會一併匯出和匯入。

「還原上一份本機資料」只用瀏覽器裡自動留下的上一份文字資料，不含附件，也不能代替匯出檔。

## API（可不用）

完全離線也能用。若要接自己的端點，到「設定 → API 端點」填：

- 名稱
- 網址（測試、拉取、推送和「問外部 API」都打這一個網址）
- 標頭名稱（預設 `Authorization`）
- 金鑰，以及「原樣放入標頭」或「加上 Bearer 前綴」
- 推送／提問用 PUT 或 POST

金鑰只存在這台裝置。只有按下按鈕時才會放進請求標頭，不會寫進主控台，也不會放進推送或提問的 JSON 本體。

| 動作 | 方法 | 說明 |
| --- | --- | --- |
| 測試連線 | GET | 顯示 HTTP 狀態和回應片段。失敗會寫明原因。 |
| 拉取 | GET | 讀取專案和記事，再選擇合併或取代。 |
| 推送 | PUT 或 POST | 送出專案和記事。不含附件，不含金鑰。 |
| 問外部 API | 與推送相同 | 送出問題、專案欄位、記事和已抽出的文件文字。預期回傳 `{ "answer": "……" }` 或純文字。 |

內建兩個不離開裝置的網址：

- `local://mock`：離線模擬。可先推送，再拉取，也可練習「問外部 API」。
- `local://fail`：固定失敗，用來確認錯誤訊息看不看得懂。

第一次打開時，設定裡已有「內建模擬」。也可按「檢查這台瀏覽器」，確認本地儲存、附件資料庫、日期計算和本機即時解答。

若要把主流 AI 接上來，請用你自己控制的轉發網址（例如公司內部服務），不要在這個 HTML 裡寫死任何廠商金鑰，也不要把合約檔放到公開網站。直接用 `file://` 打開時，瀏覽器通常會封鎖對外請求；請改在 https 開啟，或先用 `local://mock`。

### 預期的 JSON

```json
{
  "version": 3,
  "source": "project-notes",
  "exportedAt": "2026-11-25T00:00:00.000Z",
  "projects": [
    {
      "id": "p_example",
      "name": "晴灣閣升降機現代化",
      "description": "說明",
      "status": "active",
      "situation": "等候開工文件",
      "projectKind": "mod",
      "modScope": "partial",
      "machineRoom": "without",
      "retainItems": "轎廂裝潢",
      "workCommenced": "",
      "workCommencedStatus": "waiting",
      "workCommencedNote": "",
      "startDate": "2026-10-15",
      "endDate": "2027-01-15",
      "milestones": [{ "id": "m_example", "name": "驗收", "date": "2027-01-10", "done": false }],
      "tags": ["升降機"],
      "color": "#17364a",
      "createdAt": "2026-11-01T00:00:00.000Z",
      "updatedAt": "2026-11-01T00:00:00.000Z",
      "docsMeta": { "count": 1, "hasAny": true, "hasContract": true, "fingerprint": "example" },
      "verification": {
        "dates": { "verifiedAt": "", "note": "", "fingerprint": "" },
        "machine": { "verifiedAt": "", "note": "", "fingerprint": "" },
        "contract": { "verifiedAt": "", "note": "", "fingerprint": "" }
      }
    }
  ],
  "gaps": [
    {
      "id": "g_example",
      "projectId": "p_example",
      "question": "有冇機房？",
      "missing": "未填機房",
      "answered": "partial",
      "source": "manual",
      "status": "open",
      "createdAt": "2026-11-01T00:00:00.000Z",
      "updatedAt": "2026-11-01T00:00:00.000Z"
    }
  ],
  "notes": [
    {
      "id": "n_example",
      "title": "標題",
      "body": "內文",
      "projectId": "p_example",
      "createdAt": "2026-11-01T00:00:00.000Z",
      "updatedAt": "2026-11-01T00:00:00.000Z"
    }
  ]
}
```

`status` 只接受 `planning`（規劃中）、`active`（進行中）、`paused`（暫停）、`done`（已完成）、`cancelled`（已取消）。`projectKind` 為 `ni`（新裝）、`mod`（現代化）、`other` 或空白。`modScope` 為 `full`（全改）、`partial`（部分改）或空白。`machineRoom` 為 `with`（有機房）、`without`（無機房）或空白。`workCommencedStatus` 為 `waiting`、`done` 或空白。日期是 `YYYY-MM-DD`。

若請求帶了自訂標頭，瀏覽器會先送 CORS preflight。你的伺服器要允許來源，並允許 `Authorization`（或你用的標頭）和 `Content-Type`。`file://` 的來源是 `null`，所以直接打開檔案時，對外 API 通常會失敗。這時請用 `local://mock`，或把檔案放到 https 再開啟。

檔案備份比上面的同步格式多了 `format: "project-notes"`，以及可選的 `endpoints` 和 `files`（`dataBase64`，另含 `docType`、`linkLabel` 和可抽出的 `textCache`）。

## 私隱

- 沒有帳號，沒有作者架設的伺服器。
- 專案、記事、端點、金鑰和附件都在這台瀏覽器。
- 金鑰只在你按下測試、拉取、推送或「問外部 API」時，送到你填的網址。
- 頁面不會在背景連線，也沒有分析或廣告。
- 工作紀錄和合約不要放到公開網站。
